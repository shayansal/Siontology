Build on the devnet.

Everything runs on your machine: a devnet of validators that sign with two post-quantum signature families, the sion command line, a JSON HTTP API and a Model Context Protocol server for AI agents. The reference documentation lives at siontology.org/docs.

Read the documentation Get the source

Quick start

You need Rust 1.80 or later. One command starts an in-process devnet and drives real transactions through the whole protocol: lane certificates, consensus, Pulse execution, signed headers, data availability and proving. Each demo narrates what the ledger established.

The devnet is for building and learning. Its validators run in one process, its proofs are checked by replay, and its validator keys are derived from the chain name, so it secures nothing of value.

Quick start (Rust 1.80 or later)
git clone https://github.com/ColdAI-org/siontology
cd siontology
cargo build --release
alias sion=./target/release/sion

# Run every scripted demo against an in-process devnet
sion demo all --local

The demos

CommandWhat it shows
sion demo invoice --localTrade finance on insured knowledge: a bonded invoice claim is priced with the Assurance Algebra, relied on within its backing, and the financier is compensated from slashed bonds when the claim proves false.
sion demo agents --localAn AI agent with a budget the ledger enforces: a payment to an unlisted payee and an over-limit payment are refused; revoking the charter stops the agent and its sub-agent.
sion demo market --localA sealed-bid GPU-hour market that clears at one price with an optimality certificate.
sion demo receipts --localVerifiable AI inference receipts: each consumer prices the same receipt under its own assumptions.
sion demo x402 --localAn agent pays an HTTP API per request; a replayed payment and an over-limit payment are refused.
sion demo censorship --localForced inclusion: a censored user gets through by posting straight to consensus. When more than a third of a committee censors too, the shard misses its deadline, its committee is replaced, and certified headers count the overdue intent.
sion demo staking --localA standby validator stakes and joins the active set at the next epoch boundary, and a light client follows the committee change from genesis. Rewards are claimed; the newcomer signs two headers for one round, is slashed and loses its seat.
sion demo light --localA light client pins the chain identity, verifies the latest Pulse end to end and catches a node that serves substituted validator keys.

Run a devnet

A devnet and a client, in two terminals
# Terminal 1: 4 validators, 2 shards, API on port 8730
sion devnet

# Terminal 2
sion status
sion keys new dana    # dual post-quantum keys
sion faucet dana 100
sion send dana alice 12.5
sion balance dana
sion verify --chain <identity from sion devnet>

sion devnet prints the chain identity: a digest of the genesis specification, the validators with their stake and keys, and the shard layout. Pin it with --chain or SION_CHAIN, and every light-client check is made against it; without a pin, the node vouches for itself.

The client talks to the node at SION_NODE, by default http://127.0.0.1:8730. The demos also run against a live node. The staking demo needs a standby validator and epochs that end: with --local it starts such a devnet itself; for your own, run sion devnet --standby 1 --epoch-length 24.

HTTP API
curl http://127.0.0.1:8730/v1/status
curl http://127.0.0.1:8730/v1/pulses/latest
curl http://127.0.0.1:8730/v1/claims/<claim id>

# the decision rule for 25,000 USD at risk (amounts in micro-units)

Tools for AI agents

sion mcp serves the Model Context Protocol over stdio, so an agent can pay, issue claims, price a claim before relying on it, pay within an Agent Charter and verify the chain. Every transaction and receipt also comes back as a sentence. The charter’s limits are enforced by the ledger, whatever the agent was told.

MCP client configuration
{
  "mcpServers": {
    "siontology": {
      "command": "sion",
      "args": ["mcp"],
      "env": { "SION_NODE": "http://127.0.0.1:8730" }
    }
  }
}
ToolWhat it does
sion_status, sion_balance, sion_eventsChain status, balances and recent events
sion_payPays from a wallet the server holds keys for; final once the lane certificate forms
sion_issue_claimIssues a claim with a trust formula, optionally resting on the issuer’s bond
sion_assess_claimBefore relying on a claim: computes its cost of corruption under a policy and applies the decision rule
sion_agent_payPays from an Agent Charter allotment, within the charter’s payees and limits
sion_submit_intentSubmits a transaction the agent built and signed itself
sion_fetch_receipt, sion_verify_pulseFetches a receipt or a Pulse and verifies it as a light client, against a pinned chain identity
sion_fetch_paidFetches an HTTP resource that charges through x402, paying at most a cap the agent sets

x402: pay per request

x402 lets an HTTP server ask for payment with status 402 Payment Required, and lets a client, typically an agent, pay and retry without accounts, API keys or checkout pages. The adapter speaks version 2 of the protocol with an exact payment scheme on Siontology. The server answers only after verifying the payment’s receipt as a light client would, and an agent paying under a charter cannot exceed its limits.

Sell an API per request, and buy from it
sion x402 serve carol --price 0.25
# serves http://127.0.0.1:8402/v1/resource for 0.25 USD a request

sion x402 fetch http://127.0.0.1:8402/v1/resource --wallet dana --max 1

Verify as a light client

A light client pins one value, the chain identity, and checks everything else against it: the committee certificate of a Pulse, the certified order of its transactions, receipts and state proofs, random samples of its data and its World Proof. It follows committees from epoch to epoch through boundary proofs. Here is a real run of the check.

sion verify: output from a devnet run (hashes differ on every run)
chain: 6345655c matches the pinned identity; 4 validators, keys derive their identifiers ✓
Pulse 14 header d42357fe (state root aafa7aec, knowledge root b3950ae7, 0 claims)
certificate: 300000 of 400000 stake signed (quorum 266667), each signature ML-DSA-44 + SLH-DSA-SHA2-128f ✓
forced inclusion: no overdue intents (0 pending within their deadline) ✓
receipts: 1 of 1 transactions proven against the receipts root, in the certified order ✓
state: an account object proven against the state root ✓
availability: 16 of 16 random shares of the 32×32 square verified; a withholding would go unnoticed with probability < 4.7e-3 ✓
world proof: 2 leaves re-verified by stack ["A", "B"]; the published data is what executed and encodes to the certified data root (113 KB; replay proofs simulate succinct ones) ✓
lane certificates: all 1 executed transactions locked their inputs with a quorum of their shard's committee, taken from the proven validator set ✓
Measure on your machine
sion bench                 # signatures, hashing, data availability, clearing,
                           # assurance, execution, proving and a live devnet
sion bench --quick --only signatures,data
