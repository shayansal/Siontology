Trust you can check, for people and their agents.

Siontology is open source: AI agents that run on your own computer, answer in the apps where you talk and work as a team, and a ledger that holds every one of them to the limits you set. What they pay, remember and claim carries a proof or priced evidence that anyone can check.

For you: your own agent

An agent of your own, wherever you are.

It runs on your computer and answers in the apps you already use. It remembers what you tell it, works on a schedule, hands work to helpers, browses the web and runs code in a sandbox, and the ledger refuses any payment its charter forbids, whatever it is told.

Build your team.

Give each role an agent of its own, with its own model, tools, memory and budget, and talk to each wherever you like. For a job in several parts, a graph runs the parts side by side, each with its own instructions, tools or model. And one agent can hire another through a Task Charter: the ledger pays only for a result that passes the rule fixed when the task was posted.

Limits it cannot talk its way past.

Each agent has a charter on the ledger: its budget, its largest payment and whom it may pay. The ledger refuses whatever the charter forbids, even from an agent that was prompt-injected, and keeps the head of its memory log, so its past cannot be rewritten unnoticed.

Approvals

It asks before it spends

Autonomy levels from L0 to L6 decide what it does alone; by default it asks you, in the chat, before it pays. Once it has read anything from outside, it asks before reaching outside again. Each decision is kept with who made it; one made at the command line can be signed with a wallet.

Start with one command.

Install it, run setup, and talk to it, in the terminal or on the apps you connect. It all runs on your computer, apart from the model and the apps you choose.

Your own agent, on your computer
# Install sion: a release checked before it is installed,
# or built from source while there is none
curl -fsSL https://raw.githubusercontent.com/ColdAI-org/siontology/main/scripts/install.sh | sh

# A chain of your own, your agent, its model and memory
sion setup

# Talk with it; sion -c goes on with the last conversation
sion

  • One command

    Setup makes a chain of your own, your wallet and your agent’s, the agent with a budget, its memory log, its model and a profile. Run again, it changes only what it must.

  • A chain that rests

    With nothing to order, the chain waits between rounds: 5.7% of one core at rest and a transfer in 2.3 s, measured on two cores, against 98.8% without the wait.

  • Updates you can check

    sion update installs a release only once its signature, by the release key the program was built with, and its checksum hold. The release key does not exist yet, and no release has been published.

For builders: the ledger

Know what to trust before you rely on it.

Siontology is an open-source ledger for an economy in which AI agents buy, sell and publish. Payments, AI output and claims about the world carry a proof or priced evidence, so a person or an agent can check them and see what faking them would cost.

Agents with budgets the ledger enforces, APIs paid per request, receipts for AI output and markets that prove their prices: a neo-blockchain whose product is verified knowledge, not ordered transactions.

For teams deploying AI agents

Agents that cannot overspend

Give an agent a budget, a list of payees and a cap per payment. The ledger refuses any payment outside them, even from a hijacked or prompt-injected agent, and one revocation stops every sub-agent at once.

TodayAn agent’s limits live in its own code or its card’s settings, so one prompt injection can turn them into a loss.

For anyone selling an API or data

APIs paid per request

The API answers HTTP 402 with a price. An agent that calls once pays in a stablecoin; one that calls often pays from a payment stream, one hash per call. The server serves once it has checked the payment itself. No accounts, API keys or invoices.

TodayA card payment costs more than one API call, so APIs are sold as monthly plans behind accounts and keys.

For lenders and trade platforms

Invoices that repay you if they are false

Suppliers, shippers and arbiters bond what they attest. A financier funds an invoice only up to what those bonds can repay, and is repaid automatically when a challenge proves the invoice false.

For compute and energy marketplaces

Markets that prove their prices

Orders are sealed in batches and cleared at one price. A batch settles only with a certificate that no better allocation exists, so a place in the queue is worth nothing and there is nothing to front-run.

TodayMatching engines are black boxes: nobody can check that the allocation was the best available, and arrival order can be gamed.

For AI labs and anyone buying evals or training runs

Work paid only when it passes

Escrow a task with the rule a result must pass, fixed before anyone starts: the environment vendor’s bonded claim that its grader cannot be gamed, and the verifiers whose word counts. The worker is paid once, and if the grader is later proven exploitable, the buyer is repaid from the vendor’s bond.

TodayAn eval or training environment is paid for up front; if its grader turns out to reward a shortcut, the buyer absorbs the loss.

For robotics and agent builders

Memory a robot cannot rewrite

Each robot or agent keeps a log of what it saw, where and when. The ledger keeps the log’s head, lets it only grow and says when each memory was recorded. Anyone can check a complete answer to “what was in aisle 4 at 10:02”, and convict an index that hides something.

TodayAn agent’s or a robot’s memory is a file its operator can edit, so nobody can prove what it knew, and when.

For anyone who keeps data with someone else

Storage that proves itself every round

Pay per round to have data kept, fixed by its Merkle root. The provider puts up collateral and, each round, shows pieces of the data nobody could predict. A provider that cannot produce them misses the round and loses collateral. Any computer running the app can be a provider.

TodayYou take a storage provider’s word that your data is still there, until the day you need it.

Pay per call. Settle per million.

Most payments between machines are small, frequent and between the same two parties. A payment stream pays each one with a hash instead of a transaction, and the ledger settles a million of them for the cost of one. Throughput is then counted in payments, and grows with the size of a settlement, not with the size of the network.

The cost of trust, collapsed.

AI collapsed the cost of producing cognition. A neo-blockchain is designed to collapse the cost of trusting it: claims about computations, data, identities, payments and physical events that anyone can check in milliseconds.

Generation is becoming free. Verification is not.

Every AI output, agent action, image and data feed raises one question: is this real, and who pays if it is not? The cheaper generation gets, the more the bottleneck moves to checking.

Trust is the economy’s largest hidden cost.

Verification, intermediation, compliance and fraud are paid on almost every exchange between strangers. Financial-crime compliance alone costs 206 billion USD a year (LexisNexis, 2023, as cited in the architecture paper).

Blockchains sold trust in the wrong unit.

They made one thing trustworthy, their own token state, by having every node redo every computation. Siontology extends verifiable trust to anything that can carry evidence, with proofs designed to cost about the same to check for one action or a billion.

Verified knowledge, not ordered transactions.

Blockchains chain blocks and DAGs link transactions. Siontology, a neo-blockchain, folds every proof in the network into one World Proof per Pulse, designed to stay the same size however much it covers, so that a phone can check it. Four pieces carry it.

Two-sorted state

Knowledge never needs coordination. Only consuming a resource is ordered, and only among the parties contending for it.

More on two-sorted state

The Assurance Algebra

Every claim carries a formula of its assumptions. Any agent computes what an attacker must forfeit to falsify it, and acts only when that exceeds what is at stake.

More on the Assurance Algebra

Verifiable Clearing

A market batch settles only with a certificate that no better allocation exists, which the ledger checks in linear time.

More on Verifiable Clearing

The Fold

Every proof folds into one World Proof per Pulse, designed so that a phone can check the whole history without trusting a validator. Today the proofs are checked by replay.

More on the Fold

Trust becomes a number.

A claim’s formula names the assumptions it rests on: ∧ where it needs all of them, ∨ where any one route will do. Its cost of corruption is the cheapest set of failures that would make it false. An agent relies on the claim only if that cost covers κ times its value at risk, and reserves that much of the backing, so no claim is relied on beyond what slashing can repay.

Don’t trust the diagram. Run it.

Every figure on this site names the demo, specification or code behind it. The reference implementation is Rust, licensed Apache-2.0 OR MIT, and the demos drive real transactions through the whole protocol.

Quick start (Rust 1.80 or later)
git clone https://github.com/ColdAI-org/siontology
cd siontology
cargo build --release
alias sion=./target/release/sion

# Run every scripted demo against an in-process devnet
sion demo all --local

  • Two implementations of every proof

    Stack A is the reference executor. Stack B was written only from the specification. A World Proof verifies only if both accept every chunk, and CI checks that stack B never calls the reference executor’s logic.

  • A normative specification

    The state transition, version 1.15, written so that another implementation can be built from the document alone. It covers validators, stake, epochs, slashing, the response to censorship and payment streams, and pays validators from fees alone.

  • Every shortcut named

    What is built, simplified, simulated or missing is listed, and each simplification is an assumption in the trust formula of whatever the devnet reports.
