Build on the ledger.

Everything runs on your machine: a devnet whose validators sign with two post-quantum signature families, the sion command line, a JSON HTTP API, a Model Context Protocol server, and agents your programs reach over HTTP, OpenAI’s chat API and A2A. The reference documentation lives at siontology.org/docs.

Quick start

You need Rust 1.80 or later. One command starts an in-process devnet and drives real transactions through the whole protocol: lane certificates, consensus, Pulse execution, signed headers, data availability and proving. Each demo narrates what the ledger established.

The devnet is for building and learning. Its validators run in one process, its proofs are checked by replay, and its validator keys are derived from the chain name, so it secures nothing of value.

To run an agent of your own instead, sion setup makes a chain, two wallets, the agent and its memory on your computer: see Your agent.

The demos

Fourteen scripted demos, each run against a node you started or, with --local, against an in-process devnet of its own. The light demo needs a devnet that has already proven a Pulse, so it runs against a node, or inside sion demo all --local. Their recorded output is in the book.

sion demo invoice --localTrade finance on insured knowledge: a bonded invoice claim is priced with the Assurance Algebra, relied on within its backing, and the financier is compensated from slashed bonds when the claim proves false.
sion demo agents --localAn AI agent with a budget the ledger enforces: a payment to an unlisted payee and an over-limit payment are refused; revoking the charter stops the agent and its sub-agent.
sion demo swarm --localAn orchestrator and fifteen subagents, each with an identity of its own, made in three transactions: a payment over a subagent’s limit is refused, suspending the orchestrator stops a subagent two levels down, and an unspent budget is reclaimed.
sion demo batch --localSixty-four keyless subagents each pay, all authorized by one signature over the batch’s Merkle root; a batch signed by anyone but their nearest keyed ancestor is not certified.
sion demo tasks --localWork paid only when its result passes a rule fixed when the task was posted: a result without enough backing is refused, a task pays once, and a reward hack found later slashes the environment’s vendor and repays the lab.
sion demo robots --localTwo robots share a memory the ledger keeps append-only: complete answers with proofs, a rewrite refused, and an index that hides a scan convicted with a fraud proof.
sion demo storage --localA robot’s memory kept by a laptop and a phone it pays per proven round: the phone drops data, misses its rounds and forfeits its collateral; the laptop is paid.

Run a devnet

{{code:devnet}}

sion devnet prints the chain identity: a digest of the genesis specification, the validators with their stake and keys, and the shard layout. Pin it with --chain or SION_CHAIN, and every light-client check is made against it; without a pin, the node vouches for itself.

The client talks to the node at SION_NODE, by default http://127.0.0.1:8730. The demos also run against a live node. The staking demo needs a standby validator and epochs that end: with --local it starts such a devnet itself; for your own, run sion devnet --standby 1 --epoch-length 24.

With --idle-round-ms, a chain with nothing to order waits between rounds instead of running them back to back, as the chain sion setup makes does.

Your agent, from a program

sion agent serve lets programs talk to the agents on a machine, each conversation a session, with the same commands and approvals as in a chat. Every request carries a token: the machine’s, or one made for a single profile, which only approves or declines if it was made to.

The same server answers OpenAI’s chat API, so an app made for it can talk to a profile as if it were a model, and, with --a2a, other agents in A2A, versions 0.3 and 1.0. Another agent’s message counts as content from outside, so what it asks for that reaches outside or spends waits for a person. An agent gateway takes messages for profiles served from other machines, which connect out to it and prove the agent’s key.

Tested with curl and test clients, against a local devnet and a scripted model; not with those apps or with other makers’ agents. Channels, in the book

Tools for AI agents

sion mcp serves the Model Context Protocol over stdio, so an agent built anywhere can pay, issue claims, price a claim before relying on it, pay within an Agent Charter, post and settle work, keep a memory log and verify the chain. Every transaction and receipt also comes back as a sentence. The charter’s limits are enforced by the ledger, whatever the agent was told.

x402: pay per request

x402 lets an HTTP server ask for payment with status 402 Payment Required, and lets a client, typically an agent, pay and retry without accounts, API keys or checkout pages. The adapter speaks version 2 of the protocol with an exact payment scheme on Siontology. The server answers only after verifying the payment’s receipt as a light client would, and an agent paying under a charter cannot exceed its limits.

With --streams, the server also accepts the stream scheme: a client that opened a payment stream to it pays each request with the next element of its hash chain, which the server checks with one hash, and the server settles many requests in one transaction. See the guide.
