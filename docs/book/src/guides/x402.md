# x402: selling and buying an API

[x402](https://www.x402.org) revives HTTP status 402, Payment Required: a
server quotes a price, the client pays and retries, and the server serves
once the payment settles. Siontology implements x402 version 2 with an
`exact` scheme settled on the ledger. The server serves only after
verifying the payment's receipt as a light client would, and an agent can
pay under an Agent Charter, so its limits hold whatever it is told.

## How a request is paid

1. The client requests the resource. The server answers `402` with a
   `PAYMENT-REQUIRED` header: base64 JSON with the price, the payee, the
   network `sion:<first 16 bytes of the chain identity, in hex>`, and a
   fresh nonce.
2. The client signs a transfer, or a charter payment, whose purpose is
   `x402:<nonce>`, and retries with it in a `PAYMENT-SIGNATURE` header.
3. The server's facilitator submits the transaction, waits for it to
   execute, and verifies the receipt: the Pulse's committee certificate,
   the certified order and the receipt's inclusion proof.
4. Only then does the server answer `200`, with a `PAYMENT-RESPONSE`
   header describing the settlement.

Each quote and each transaction pays for one request. A quote is valid for
300 seconds. Replaying a payment fails: the nonce is used up.

## Sell an API

```text
Usage: sion x402 serve [OPTIONS] <PAY_TO>

Arguments:
  <PAY_TO>  Who gets paid (wallet name or account ID)

Options:
      --listen <LISTEN>  Listen address [default: 127.0.0.1:8402]
      --path <PATH>      The resource's path [default: /v1/resource]
      --price <PRICE>    Price per request (USD) [default: 0.25]
      --body <BODY>      What every paid request returns [default: {"paid":true}]
      --chain <CHAIN>    The chain identity receipts must verify against. Without it the node vouches for itself [env: SION_CHAIN=]
```

```text
$ sion x402 serve carol --price 0.25 --chain 6345655cfd2a714ed1dab69c0660f2f48f429ce2981e25629d0467d7b7ee97b7
selling http://127.0.0.1:8402/v1/resource at 0.25 USD per request, paid to a08c0fc6 on sion:6345655cfd2a714ed1dab69c0660f2f4
```

`sion x402 serve` serves one resource with a fixed body. It is a working
reference for the server side; a real API would use the same flow from its
own code (`sion_cli::x402`).

An unpaid request:

```text
$ curl -si http://127.0.0.1:8402/v1/resource
```

The header carries the same JSON as the body, base64-encoded (cut here).
`amount` is in micro-units; `extra.chain` is the full chain identity, and
`extra.purpose` is what the payment must name.

## Buy from it

```text
Usage: sion x402 fetch [OPTIONS] --wallet <WALLET> <URL>

Options:
      --wallet <WALLET>        The paying wallet (the agent's, when paying under a charter)
      --charter <CHARTER>      Pay under this Agent Charter (ID) instead of by transfer
      --allotment <ALLOTMENT>  The agent's allotment (ID), with --charter
      --max <MAX>              The most to pay (USD) [default: 1]
      --chain <CHAIN>          The chain identity to pay on. Without it the node vouches for itself [env: SION_CHAIN=]
```

By transfer:

```text
$ sion x402 fetch http://127.0.0.1:8402/v1/resource --wallet dana --max 1 --chain 6345655cfd2a714ed1dab69c0660f2f48f429ce2981e25629d0467d7b7ee97b7
402 Payment Required: 0.25 USD to a08c0fc672bb5875d68526c0e9b1a3bbe5f57652e6af18a174dbb39c0ad93670 on sion:6345655cfd2a714ed1dab69c0660f2f4
paid: transaction 95c6d7b23b25276ac7cb10cb2a83622cf3192afc11fbdedf7f263de57e7534be settled and verified by the server
200 {"paid":true}
```

The whole round trip took 8 seconds on the devnet, most of it waiting for
the Pulse. A client refuses to pay more than `--max`:

```text
$ sion x402 fetch http://127.0.0.1:8402/v1/resource --wallet dana --max 0.1 --chain 6345655cfd2a714ed1dab69c0660f2f48f429ce2981e25629d0467d7b7ee97b7
error: the server asks 0.25 USD, more than the 0.1 USD this client may pay
```

## Buy as an agent, under a charter

The principal charters the agent to pay only carol, at most 0.50 USD per
payment and 1 USD per 1,000 Pulses:

```text
$ sion charter create acme agent8 --payees carol --max-payment 0.5 --max-window 1 --funding 5
acme signs: Give agent8 an Agent Charter funded with 5 USD: only to carol, at most 0.5 USD per payment, 1 USD per 1000 Pulses, until Pulse 100191, a receipt claim for every payment, may delegate narrower limits. Fee 0.0011 USD; valid until Pulse 211.
Pulse 193: Done: charter e2737343 created; fee 0.0011 USD.
  digest 3d21f132485c10d1d08678bef68083569d4e8ec6cba169f88b3722eeb1f0f342
charter e2737343d3417c1d1ab57608493535275ec9df51411e6d61f0d1748d6953d218
allotment 755f14bad8d27e3c6605f23d95c478406a14e92e62e1989a3588c934c4a3bf7f

$ sion x402 fetch http://127.0.0.1:8402/v1/resource --wallet agent8 --charter e2737343d3417c1d1ab57608493535275ec9df51411e6d61f0d1748d6953d218 --allotment 755f14bad8d27e3c6605f23d95c478406a14e92e62e1989a3588c934c4a3bf7f --max 1 --chain 6345655cfd2a714ed1dab69c0660f2f48f429ce2981e25629d0467d7b7ee97b7
402 Payment Required: 0.25 USD to a08c0fc672bb5875d68526c0e9b1a3bbe5f57652e6af18a174dbb39c0ad93670 on sion:6345655cfd2a714ed1dab69c0660f2f4
paid: transaction e6648770a7fa5545fd40b0aca06356399da0d050c1daf0e86b73184a01f57afd settled and verified by the server
200 {"paid":true}
```

The payment is an `AgentPay` from the agent's allotment. If the server had
asked for more than the charter allows, or named another payee, the ledger
would have refused the payment and the server would have served nothing.
The `x402` demo shows that case:

```text
           agent: GET /v1/report (5 USD) → pays → the ledger refused the payment: charter caveat violated: payment 5 above per-payment limit 1; carol's API answers 402 and serves nothing
```

## For agents over MCP

The MCP tool `sion_fetch_paid` does what `sion x402 fetch` does, with a cap
the agent sets per call; see [MCP tools](../reference/mcp.md#sion_fetch_paid).

## Limits

- The adapter speaks x402's headers and JSON, but it has not been tested
  against third-party x402 clients or servers.
- EVM payment schemes are out of scope; the only scheme is `exact` on
  `sion:` networks.
- One quote pays for one request; there are no sessions or prepaid
  balances.
